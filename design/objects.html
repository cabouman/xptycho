Objects and Data

How the five kinds of quantities from the theory page map onto objects. The layout is the mbirtorch pattern, chosen by Charlie on 2026-10-03 after Claude and Vera reached it independently: one model holds the parameters and the forward model, and the unknowns pass through it as arguments and results. recon returns a Reconstruction: the two unknowns with the record of the run. Position refinement is a method the user calls (section 6). Two points remain open (section 7).

1. The three things a user holds

Scan

The measurement. Never modified.
  • data the frames \(y_j\), in memory or read from a file in batches.
  • facts from the file positions, wavelength, distance, detector pixel, as recorded. Read once, to build a model.
  • Made by Scan.load(path), by model.simulate, or by preprocessing raw frames.

PtychoModel

The parameters and the forward model. Holds no image and no probe.
  • fmodel_params fixed when the model is built.
  • recon_params and compute_params set and read by name.
  • Computes the forward model, simulates data, and reconstructs. Drawn in full below.

The unknowns, and Reconstruction

The unknowns go in as arguments. They come back inside a Reconstruction.
  • unknowns the object image \(x\), complex, on the object grid; the probe modes \(d\), complex \((K, N_p, N_p)\). Given to forward and simulate; given to recon when known.
  • recon returns a Reconstruction holding both unknowns (object, probe) and the record of the run: the parameter table the run used, the pixel size, origin, and coverage needed to read the image, and the data-error curve. Drawn in section 3.
  • It saves itself to a folder and loads back, so a cluster job's output is one thing.

The run state is the fourth kind and nobody holds it: it exists inside recon and is gone when recon returns.

2. The model, in full

PtychoModel

Forward-model parameters

Given to the constructor, or read from a scan by from_scan. Fixed for the life of the model.
  • wavelength (or energy)
  • object-to-detector distance
  • detector pixel pitch
  • frame size \(N_p\)
  • scan positions, in meters
  • \(K\), the number of probe modes

Reconstruction parameters

set_params(...) and get_params(...), by name. Defaults from the 2025 paper and the old code.
  • object_data_fit \(\alpha_1\), probe_data_fit \(\alpha_2\)
  • probe_weight_exponent \(\kappa\), relaxation \(\rho\)
  • mode_schedule, mode_energy_fraction
  • initial_probe_distance
  • object grid shape (must hold every patch)

Compute settings

configure_devices(...). Change where the arithmetic runs, never the answer.
  • the devices: a count, or a list
  • the batch size (automatic unless set)

Derived from the forward-model parameters, read-only: the object pixel size \(\lambda L / (N_p \Delta_{\mathrm{det}})\), the positions in pixels, the object grid shape and origin, the patch operators \(P_j\).

Methods

Written as a user calls them: PtychoModel(…) builds one, and model.name(…) is a method of the instance model. The one classmethod is marked.

PtychoModel(…) constructorBuild from the forward-model parameters.
PtychoModel.from_scan(scan, probe_modes=1, **overrides) classmethodBuild from the facts a scan file recorded. Any parameter passed overrides the file's value.
model.set_params(**p), model.get_params(names)Set and read reconstruction parameters and compute settings by name, as in mbirtorch.
model.configure_devices(num_devices=1, devices=None)Choose the devices, as in mbirtorch: a count of GPUs, or an explicit list. Without a call the model chooses automatically. See Computing, section 4.
model.print_params()Print every parameter with its value, units, and origin (given, file, derived, default).
model.forward(x, d)The forward model. For every scan position: cut the patch out of x, multiply by each probe mode, far-field transform, sum the modes in intensity. Returns the noiseless amplitudes \(y_j\), shape \((J, N_p, N_p)\). Stores nothing.
model.simulate(x, d, pixel_size=None, peak_photons=None, dark_rate=0, seed=0)Calls forward, after checking that pixel_size, when given, equals the model's object pixel size, scales the intensities so the brightest sample is peak_photons, draws Poisson counts, and returns a Scan carrying this model's positions and instrument facts. Without peak_photons, the exact intensities.
model.recon(scan, probe=None, init_probe=None, init=None, iterations=…)The reconstruction. With probe=, the probe is known and held fixed. Without it, the probe is estimated: from init_probe= when given, else from the data-driven initialization. A given probe= must have all \(K\) modes. An estimate may start with fewer: one mode from the initialization, or however many init_probe= has, and reaches \(K\) by adding a mode at each iteration of mode_schedule (theory page, section 5). The schedule must have enough entries to reach \(K\), or recon refuses before it starts. init= warm-starts both unknowns from a previous Reconstruction. iterations is the one setting that changes on every call, so it is an argument here, as mbirtorch's max_iterations is. Returns a Reconstruction. The run state lives only inside this call.
model.data_error(scan, x, d)The normalized distance between forward(x, d) and the scan's amplitudes. The curve recon reports, available on its own.
model.refine_positions(scan, x, d, max_shift=1)One refinement pass: for each position, the integer shift within max_shift whose forward best matches the data, given x and d. Returns the refined positions and the per-position misfit. Changes nothing. Section 6.
model.initial_probe(scan), model.initial_object(scan, d)The two initialization formulas of the theory page, exposed so a user can look at the starting point. recon calls them when nothing is given.

3. Two directions through one model

The forward model is written once, in forward. Everything else that needs it calls it.

simulation: known \(x\) and \(d\) in, data out
x, da known object and probe
→
model.simulate(x, d, …)forward, then Poisson counts
→
Scanframes, positions, facts
reconstruction: data in, \(x\) (and \(d\)) out
Scanframes, positions, facts
→
model.recon(scan, probe=…)PMACE; the run state lives here
→
Reconstructionx̂, d̂, and the record of the run

Two more uses share the same forward: data_error, and refine_positions, which compares forward at shifted positions against the data. A continued run is another recon call on the same model with init= the previous Reconstruction.

What recon returns

A Reconstruction holds two things and nothing else: the unknowns, and a record of the run. The record is not a new kind of quantity; it is copies and derived values of what the model holds, frozen at the time of the run. Nothing of the run state and nothing of the measured data comes back.

Reconstruction

The unknowns

Estimated, or given to recon and passed back, so the object is complete on its own.
  • object: \(\hat x\), complex, on the object grid
  • probe: \(\hat d\), complex \((K, N_p, N_p)\)

To read the image

Derived from the forward-model parameters and the probe.
  • pixel_size, origin: where the grid sits, in meters
  • coverage: the accumulated probe weight; zero where no probe reached
  • mode_energies: the share of the probe energy in each mode
  • positions: the positions the run used

The record of the run

What model.print_params() showed, plus what happened.
  • params: fmodel_params, recon_params, compute_params, each with its origin
  • curves: the data error per iteration; object and probe error when a truth is given
  • iterations run, time, devices

Methods

recon.summary()The parameter table as text, then the iteration count, the final errors, the time, and the devices.
recon.show(directory=None, compare_to=None)Magnitude and phase of the object over the coverage, the probe modes with their energy fractions, and the curves. With a truth, the error images and the NRMSE.
recon.save(directory)One folder: summary.txt, parameters.csv, recon.h5 (object, probe, positions, coverage, curves, with pixel size and origin as attributes), preview images, plots/. recon.h5 is the file a laminography reconstruction reads.
Reconstruction.load(directory) classmethodRead a folder written by save.

How the probe reaches \(K\) modes

Mode addition is inside recon. The user sets the target and the timing: \(K\) on the model (probe_modes=2) is how many modes the run ends with; mode_schedule=[20] is the iterations at which a mode is added; mode_energy_fraction is the energy a new mode starts with. recon starts with one mode (or the modes in init_probe=) and at each scheduled iteration runs the six steps of theory section 5. The user sees it in three places: the progress line printed at that iteration ("iteration 20: mode 2 added, 5% of the energy"); recon.curves, which carries a probe-error curve per mode when a truth is given; and the result, recon.probe of shape \((K, N_p, N_p)\) with recon.mode_energies, the final share of each mode.

4. The scripts

# 1. simulated scan, known probe (TCI 2023, Fig. 6)
truth = xptycho.demo_truth('synthetic')                            # truth.object, truth.probe, truth.pixel_size
model = xptycho.PtychoModel(energy=8.8, detector_distance=L, detector_pixel=p,
                            frame_size=256, positions=pos, probe_modes=1)
scan = model.simulate(truth.object, truth.probe, pixel_size=truth.pixel_size, peak_photons=1e4, seed=0)
model.set_params(object_data_fit=0.6, probe_weight_exponent=1.25, relaxation=0.5)
model.print_params()
recon = model.recon(scan, probe=truth.probe, iterations=100)      # probe given, held fixed
print(xptycho.nrmse(recon.object, truth.object))
recon.show(OUTPUT_DIR, compare_to=truth); recon.save(OUTPUT_DIR)

# 2. measured scan, blind, two modes (TCI 2025)
scan = xptycho.Scan.load('gold_balls.h5')
model = xptycho.PtychoModel.from_scan(scan, probe_modes=2)         # fmodel_params from the file
model.set_params(object_data_fit=0.5, probe_data_fit=0.6, mode_schedule=[20],
                 initial_probe_distance=0.3e-6)
model.configure_devices(num_devices=4, batch_size=512)
recon = model.recon(scan, iterations=200)                         # probe not given, so estimated
recon.probe                                                       # (2, h, w)
recon = model.recon(scan, init=recon, iterations=100)             # continue from the previous result
recon.save(OUTPUT_DIR)

5. Where each kind lives

kindlives in
measured dataScan
fmodel_paramsPtychoModel, fixed at construction; a copy of the recorded ones in Scan
unknownsarguments of forward, simulate, recon; returned inside a Reconstruction
recon_paramsPtychoModel, set_params
compute_paramsPtychoModel, configure_devices
run stateinside recon
Why the unknowns are not in the model. The same probe is fixed in one run and estimated in the next; an argument states which, an attribute cannot. The object's size depends on the object grid, a reconstruction parameter, so it cannot exist when the model is built. And the image goes straight to mbirtorch, whose users already write image = model.recon(data).

6. Position refinement

Positions are a forward-model parameter, read from the scan file, and in most runs they are accurate enough to leave alone. Sometimes they are not, and the user usually knows which from the instrument. So refinement is a method the user calls, never something recon does on its own.

The method is Qiuchen's: for each position, try every integer shift within max_shift, run forward at each against the current object and probe, and keep the shift that best matches the measurement. It trusts the current image, so it is called after some iterations, and it costs 9 to 25 forward projections per position per pass.

recon = model.recon(scan, iterations=50)
new_pos, misfit = model.refine_positions(scan, recon.object, recon.probe, max_shift=1)
model.set_params(positions=new_pos)                       # accept the refined positions
recon = model.recon(scan, init=recon, iterations=150)     # continue with them
  • refine_positions changes nothing. It returns the refined positions and, per position, how much better the best shift fits than the current one. A user who sees nothing to gain leaves the positions alone.
  • The user accepts a change with set_params(positions=...). The scan keeps the recorded positions, so the correction is always visible as the difference.
  • Several rounds are several recon calls, each a warm start from the previous Reconstruction.

7. Open points

Decided 2026-10-03: recon returns a Reconstruction (section 3); iterations is an argument of recon.

  1. Continuing a run. init=recon rebuilds the per-position copies from the averages, so a continued run is not identical to one uninterrupted run of the same length. Acceptable for a warm start.
  2. Laminography series. One model per scan, since the positions differ per tilt, or one model holding all of them.
